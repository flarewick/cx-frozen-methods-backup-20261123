## 3. 从一次查询到下一次更新的完整流程

1. **实际当前观测与一次采样。** `ActorQuery`读取当前三路RGB、自己的14维命令状态、语言及合法历史，每次查询只运行一次原base采样，并只使用一次原内部噪声。保存原base动作 `a_base∈R^(32×14)`、冻结full残差 `r0`、隐藏状态 `h∈R^(32×64)` 和logits。诊断用物理状态/RNG摘要不进入策略特征。
2. **原事件选择与动作执行。** 原 `EventDetector/LocalController` 产生事件机会。TTA只替换被选中的ARM残差方向；未激活事件时不将返回方向强行施加到动作。执行原生32命令chunk，按仿真实际物理步采集位置目标、速度目标、夹爪逻辑命令和dt，不以计划动作冒充实际已执行前缀。
3. **关联与局部跟踪。** 初始head RGB和语言通过冻结GroundingDINO+SAM获取两个对象及角色；之后SAM2只处理已到达的同一对象前缀。事件源保留自己的掩码历史，不把其他场景或未来帧借来补齐。
4. **按实际执行阶段等待反馈。** 源chunk必须32条命令真实返回，取得实际命令执行进度95%的物理时刻。只有窗口起点不早于该阶段、窗口终点至少晚0.25秒、全部帧与命令均已到达，反馈才可能释放。原生成功/步数终止导致的不完整chunk保留为censor，不编造完整反馈。
5. **绑定真正发出命令的查询。** 局部行按自己的 `command_query` 取当时的隐藏状态；origin与following分别属于源查询q和q+1。只在实际q+1/q+2查询边界消费单次packet，不能把following命令错误地配给源q的隐藏状态。
6. **两步在线更新与信任检查。** 使用同一packet做两步快参数梯度更新；响应损失必须下降，且信任约束通过。失败则回滚该次提议的快参数。无新packet时不重复更新，可继续使用先前通过检查的快参数。
7. **只影响后续真正执行的动作。** 通过的快参数改变当前及后续查询的ARM方向，但最终动作仍由原事件激活逻辑控制。区分packet接受、方向改变、事件激活、实际动作改变和最终成功，不能用其中任一中间信号替代任务收益。
8. **回合结束清空。** 每个branch独立创建session；gain/offset从零开始，anchors和packet队列独立，结束清空；冻结模型参数与buffers不变。

- head图像为240×320；局部窗口固定25..125个**实际物理步**，不是25..125条策略命令或墙钟毫秒。

## 5. 数学实现与固定超参数

### 5.1 128个快参数与ARM可见更新

快参数为 `φ=(g,b)`，各64维。响应网络是 `122 → 64 → 388` 的MLP，中间SiLU；122=隐藏均值64+标准化context53+kind5，388=2×194。

原full头ARM读出 `W∈R^(12×64)` 固定、满行秩12。从其SVD得到行空间正交投影 `P=VᵀV`，满足 `WP=W`。**只投影快扰动，保留原隐藏条件本身：**

```text
hbar = mean_time(h)
delta_h = P(hbar ⊙ g + b)
y_hat(φ) = K(x,u,kind) +
  < reshape(Bθ[hbar+delta_h,x_norm,kind] - Bθ[hbar,x_norm,kind]),
    u / action_scale > / 194
```

P限制响应模型只能通过ARM读出可见的扰动解释物理反馈，避免代理损失在动作不可见方向上下降。P是固定buffer，和原策略的projection.npz是不同对象。

实际ARM方向使用每个动作offset的hidden，而非hbar：

```text
rφ = clip(r0 + 0.1 * (tanh(logits_ARM + W(h ⊙ g + b))
                    - tanh(logits_ARM + 0)), -0.1, 0.1)
```

φ=0时该差分精确为零，返回原r0。最后原composer仅在active事件应用ARM残差，两个夹爪通道6/13始终保持base命令。

### 5.2 在线更新与回滚

| 项目 | 固定值 |
| --- | --- |
| 每packet内循环 | 2步SGD式梯度更新 |
| learning rate | 0.05 |
| 联合gain/offset梯度范数限幅 | 1.0 |
| 响应损失 | `mean(((y_hat-y)/0.003125)^2)` |
| 接受条件 | 参数确实改变、packet响应loss严格下降、trust通过 |
| 快参数联合L2范数 | ≤0.25 |
| 相对原r0的最大ARM方向改变量 | ≤0.02 |
| 与原r0方向余弦 | ≥0.8；零向量按源代码特例处理 |
| 原anchor上的最大方向漂移 | ≤0.02 |
| anchors | 最近最多2个已接受更新时的当前查询 |
| 每回合源/packet预算 | 最多3次尝试，每packet仅消费一次；不是每个查询都更新 |
| ARM最终残差上限 | ±0.1 |
| GRIP残差 | 0 |

提议更新失败时恢复上一快参数；输出当前动作前还会重新检查trust，若不满足则输出原r0。无packet不做额外优化，也不以在线成功/专家动作当作loss。
